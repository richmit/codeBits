* STM32 Project Template

This directory contains a template for STM32 projects.  

*WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING*

I'm actively working to transition the CMake configuration I have been using for some time into something more suitable for public consumption.  As such I expect it to change in the future.

*WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING -- WARNING*

** About My Embedded Development

 - Primary development platform is MSYS2 inside of Windows 11 on x86
 - Secondary development platform is Debian on both x86 and Arm64
 - Most development work is done inside of Emacs (Edit, build, program, debug, eshell)
 - STM32 cores: F4, G4, L4, & F7.
 - Projects are initially generated & later updated with STM32CubeMX.  They use both CMSIS & HAL.
 - MCUs are used via Nucleo & Discovery boards -- both for development and as project components
 - CMake for build generation & Ninja for builds
 - Debug probes include (listed by preference):
   - Standalone J-Link via standard 10-pin header
   - Standalone ST-Link V3 via standard 10-pin header
   - Various onboard ST-Link probes
 - Command line tools are managed via [[https://github.com/richmit/verGo][verGo]] or the [[STM32 Cube Bundle Manager][STM32 Cube Bundle Manager]]. CMake builds always use CBM.
 - Debug output is via UART (usually one tied to an onboard ST-Link VCP), SWO, RTT, and semihosting.
 - Primary debugger is GDB using the [[https://openocd.org/][OpenOCD]], ST-link, J-link GDB server via GUD inside Emacs.
 - Occasionally use Segger's Ozone debugger as well.
 - Well equipped electronics workbench with extensive tool automation capabilities

* Project Organization

The project organization scheme I use is a simple extension of what STM32CubeMX provides.  
 
** Some Top Level Components

| File                                          | Description                                                 |
|-----------------------------------------------+-------------------------------------------------------------|
| ~PROJECT_NAME/PROJECT_NAME.ioc~               | STM32CubeMX project file.                                   |
| ~PROJECT_NAME/CMakeLists.txt~                 | STM32CubeMX will not update this file unless it is missing. |
| ~PROJECT_NAME/CMakeLists.txt.YYYYMMDDhhmmss~  | Backup of a STM32CubeMX generated CMakeLists.txt file.      |
| ~PROJECT_NAME/CMakePresets.json~              | Unmodified CMakePresets.json generated by STM32CubeMX.      |
| ~PROJECT_NAME/Core/Src/main.c~                | Source file with main() function.                           |
| ~PROJECT_NAME/Core/Src/main.c.YYYYMMDDhhmmss~ | Backup of main.c                                            |
| ~PROJECT_NAME/build/Debug/~                   | Build directory for debug builds (O_DEBUG=1).               |
| ~PROJECT_NAME/build/Release/~                 | Build directory for production builds (O_DEBUG=0).          |
| ~PROJECT_NAME/Mainly/Inc/mainly.h~            | Header file with ~mainly()~ declaration.                    |
| ~PROJECT_NAME/Mainly/Src/Mainly.cpp~          | Source file with ~mainly()~ function.                       |
| ~PROJECT_NAME/PROJECT_NAME.jdebug~            | Segger Ozone configuration.  Usually saved by Ozone.        |
| ~PROJECT_NAME/PROJECT_NAME.jdebug.user~       | Segger Ozone configuration.  Usually saved by Ozone.        |
| ~PROJECT_NAME/.settings/~                     | Cube Bundle Mangier Project configuration.                  |
| ~PROJECT_NAME/proj_config.cmake~              | Various project configuration options.                      |
| ~PROJECT_NAME/update_from_template.sh~        | Update project files from template.                         |
| ~PROJECT_NAME/update_main.sh~                 | Update main.c to call ~mainly()~                            |
| ~PROJECT_NAME/cmake_build_templates~          | Templates that get expanded into the build directory        |
|                                               |                                                             |

* STM32 Cube Bundle Manager

The bundle manager is part of the STM's VS Code extension.  You can find the binary in the extension's install directory.
As of 2026-08-27 on my Windows machine, that is here:

#+begin_src example
%USERPROFILE%\.vscode\extensions\stmicroelectronics.stm32cube-ide-core-1.2.1-win32-x64\resources\binaries\win32\x86_64\cube.exe
#+end_src

This tool can be used outside of VS Code.  For example, we can build an STM32 VS Code CMake project from the command line by
running ~cube cmake~ in the root of the project directory.
